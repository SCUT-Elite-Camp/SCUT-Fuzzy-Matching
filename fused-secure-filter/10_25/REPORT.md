# 第二部分：改动方案与改动的代码文件

## 2.1 改动 1：kernel 实现优化

**文件**：`party_b/online_responder.py`，函数 `tiled_batch_matching()` 内层循环。

**改前**：

```python
plain_i = (B_tile[i, :, f] * R).reshape(-1)
term = enc_selectors[i] * plain_i.tolist()          # TenSEAL 内部把 list 再转一遍
acc_f = term if acc_f is None else acc_f + term     # 每次分配新密文
```

**改后**：

```python
plain_i = (B_tile[i, :, f] * R).reshape(-1)
term = enc_selectors[i] * ts.plain_tensor(plain_i, dtype="float")
if acc_f is None:
    acc_f = term
else:
    acc_f += term                                    # in-place，避免 k-1 次分配
```

**原理**：
- `plain_tensor` 直接构造 TenSEAL 的明文对象，省掉 `list` → 内部再转换的一趟；
- `+=` 走 `__iadd__`，避免 49 次新密文分配。

**语义影响**：无。两处都是操作数传递方式的变化，不改变数学结构。
实测 `max|diff| = 0`，逐位一致。

**收益**：取决于 tenseal 轮子，1.00×–1.11×。

## 2.2 改动 2：固定截断 c=483→400

**文件**：`config/params.py` → `TRUNCATED_CANDIDATE_COLUMNS = 400`

**内容**：候选矩阵从 483 列截到 400 列，tiles 25 → 20。

**为什么零泄漏**：截断是**公开的固定形状**，与数据无关。B 侧没有增加任何
对 A 私有信息的观察；A 侧也没有新增输出。

**代价**：位置覆盖 0.995，即丢弃 0.5% 的尾部候选列。

## 2.3 改动 3：阈值 τ 0.90→0.84

**文件**：`config/params.py` → `SIMILARITY_THRESHOLD = 0.84`

**依据**（独立 dev/test，各 600 条，与调参集完全分离）：

| τ | test 召回 | FPR |
|---|---|---|
| 0.90 | 0.805 | 0/600 |
| **0.84** | **0.883** | 1/600 |

**注意**：这是**操作点移动**，不是算法加速。计算量完全不变。

# 第三部分：尝试过并排除的改进

## 3.1 一页表

| # | 尝试 | 预期 | 实际结果 | 排除了什么 |
|---|---|---|---|---|
| 1 | 均衡聚类压 max_size | 483→200 无损降本 | 召回 **0.880→0.750**，新增 13 漏报（p=2.4e-4） | 形状压缩的无损空间 |
| 2 | 改候选组织（k/L 搭配） | 更优组织降本 | 三组耗时差 **2.4%** | 组织方式作为成本变量 |
| 3 | 槽位打包 | 减少乘法次数 | 成本与槽位数无关；利用率已 97.7% | 打包作为优化轴 |
| 4 | 代数外提掩码 R | 省掉内层乘法 | **`scale out of bounds`** | 代数重写的可行性（深度只有 2 层） |
| 5 | 组级共享形状 | 填截断与分带之间的空隙 | 小组被 tile 粒度拖死，大组退化 | 「中间折中」的存在性 |
| 6 | R3 份额同态重构 | 把 PSI 输出接进 CKKS | 数值完美（零错误），但**不减少任何计算** | 「重构标志」作为性能路线 |
| 7 | 两阶段维度拼接 | 25+25=50 | 算术上零节省 | 该方向 |
| 8 | 多分辨率 | 分层剪枝 | 各维 iid，退化为选 d | 该方向 |
| 9 | 自适应精度 | 粗筛降本 | 阈值校准能控 FPR，补不回判别力 | 该方向 |
| 10 | **平衡树归约**（Wallace 式） | 更浅计算图 | **0.889×，慢 12.5%** | 树归约在 CKKS 上不适用 |
| 11 | 明文预计算向量化 | 减少 NumPy 调用 | **1.002×** | 该方向 |

## 3.2 第 10 条值得单独展开

Wallace 树的价值来自「降低加法器深度」，但那条推理在 CKKS 上不成立：

1. **密文-密文加法不消耗模数层级**，所以「深度下降」的收益为零；
2. 平衡树必须在归约前**同时持有 k=50 个密文**，而串行累加任意时刻只有约 2 个活密文；
3. 密文对象很大（4,000 槽），额外内存与分配器压力超过了依赖结构的改善。

**实测**：向量化预计算 + 平衡树 = 0.889×（慢 12.5%）；
只保留向量化预计算 + 串行累加 = 1.002×（无变化）。
两者输出都逐位一致（`max|diff| = 0`）。

**结论：在「加法无深度成本 + 密文对象很大」的组合下，更浅的计算图是负优化。**

## 3.3 成本结构（实测，单 tile）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| ct-pt 乘（2,500 次） | 2.207 s | **88.1%** |
| 明文构造 + 转换（2,500 次） | 0.161 s | 6.4% |
| ct-ct 加（2,450 次） | 0.073 s | 2.9% |
| 点积（50 次 ct-ct 乘） | 0.065 s | 2.6% |

**为什么结构改造空间很小**：

- 单次乘法 0.883 ms，已贴近 NTT 下限；
- 次数 `k·d = 2,500` 是「对 d 个特征各做一次 1-of-k 隐藏选择」的下界；
- 槽位利用率 97.7%，每次乘法已满载。

三者同时顶到边界。

## 4.2 已经取得的成果（独立系统，未整合）

| 指标 | 原始 | 优化后 | 变化 |
|---|---|---|---|
| n=1000 端到端 | 213.14 s | **85.66 s** | **2.51×** |
| EMP 网络往返 | 729,303 | **576** | **1,266×** |
| reveal 阶段 | 53.0 ms/轮 | **10.5 ms/轮** | 5.0× |
| 规模参数 | 只能 Q=N | Q、N 可分别指定 | 新能力 |

**这个 2.51× 不能与 CKKS 的 1.23–1.38× 相加或比较**：
匹配语义不同（Hamming vs 余弦），且两者从未串成一个可运行系统。

### 优化做了什么

`secureFilterBatch()` 的 Phase 3：原本每个 bin 调两次 `reveal`（分别给 ALICE 和 BOB），
改为每轮一次批量 `reveal_bits` 揭示给 PUBLIC。

- 揭示的位与接收方完全不变，只是把 `2m` 次网络往返合并成 1 次；
- 逐轮匹配数与基线完全一致（108 轮 diff 无差异）；
- 网络往返 729,303 → 576，正好对应 `1274 bins × 2 × 286 轮 ≈ 72.9 万`。

## 4.3 尝试过但失败的

| 尝试 | 结果 | 根因 |
|---|---|---|
| **跨轮 PSI 批处理** | 108 轮只完成 42 轮，匹配数错位为 14/24/36 | `local_valid=false` 的 bin 其 `my_id` 恒为 0，按 `my_id/SHIFT` 拆分时全落入 round 0 |
| **ℓ=128→64** | GC 加速 1.81×，但**未获放行** | 6 次运行 90 万 bins 零误报，但 95% 上界 2×10⁻⁵ 对两个 ℓ 相同，样本无法区分 |
| PSI 单次扩展性 | `T ≈ 144 ms + 0.0297 ms/项` | 用于估算，非实测收益 |

### 跨轮批处理为什么不是「改个编码就能修」

PSI 对每个 bin 只返回本方的 `my_id` / `local_valid`；本方没有输入的行被填
`id=0, valid=false`。因此**任何一个 bin 最多只有一方知道它属于哪一轮**。
而批处理要求双方对「这个 bin 归哪一轮」有一致的公开判断
（`compare_mask` 依赖轮次，批次边界必须同步）。**信息不存在，编码无法凭空产生。**

### ℓ=64 为什么不能放行

| ℓ | 比较位数 | 单候选误判概率（二项模型） |
|---|---|---|
| 128 | 65 | 3×10⁻¹² |
| 64 | 32 | **1.4×10⁻⁵** |

15 万候选下 ℓ=64 的期望误报约 2.1 次；观察到 0 在泊松下概率 12%——
**不算反常，但不足以证明误报率为零**。要区分两者需要 10⁷ 量级候选 bins。

## 4.4 为什么没有做融合

| 方向 | 阻塞点 |
|---|---|
| A. PSI 候选 → CKKS 精排 | PSI 给出约 2 条候选，但隐藏「选了哪 2 条」仍需对全部 483 列加权求和；选择维度从簇(50)变成记录(483)，**乘法 ×9.7** |
| B. CKKS + GC 阈值判定 | CKKS 分数用 A 的单密钥加密；GC 要判定，A 必须先解密——**那时 A 已看到分数，GC 失去意义** |
| C. 不透明候选编码 | 随机 ID/哈希只是**工程匿名**，不构成密码学保护；且当前流程本就不向 B 暴露候选身份 |

## 4.5 可能性分析：未来值得做什么

按可行性排序：

### 1. 统一匹配语义（前提条件）

CKKS 做余弦、PSI 做 Hamming，两者判定函数不同，任何耗时对比都不成立。
要么让 CKKS 侧也做 Hamming 判定，要么把 PSI 侧接上余弦。
**这是所有公平比较与融合的先决条件。**

### 2. 门限 CKKS（真正的融合入口）

当前 CKKS 用 A 的单密钥，A 解密即见分数，GC 无法介入。
若改为 A、B 合作解密（门限方案），分数可以只以份额形式存在，
GC 才能在**不暴露分数**的前提下做私密阈值判定——这正是方向 B 想要的能力。
**代价**：换协议，不是加模块。

### 3. 跨轮 PSI 批处理（需新增泄漏）

要么让 PSI 额外公开每个 bin 的轮次标签（**新增每轮 bins 数量的侧信道**），
要么重新设计 PSI 输出结构使其携带轮次。当前选择不引入该泄漏。

### 4. ℓ 的误报审计（规模问题，非算法问题）

需要 10⁷ 量级候选 bins（约为当前 60 倍），在本机约数小时。

## 4.6 建议

**短期**：不要再投入 PSI/GC 与 CKKS 的融合。现有接口下没有同时满足
「语义不变 + 不新增泄漏 + 成本更低」的方案。

**中期**：若要继续融合研究，应先做「统一匹配语义」——这是成本最低、
且是其他所有工作的前提。

**长期**：门限 CKKS 是唯一能让 GC 真正发挥作用的路径，但属于新的协议设计任务。
