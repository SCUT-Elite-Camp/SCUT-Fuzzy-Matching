# 多语言多属性 10k / 200 基准

独立新建的数据版本，保留原 `fused_multilingual` 300 / 50 与 demo10，不覆盖旧结果。
姓名来自本地 SAGE 原始 CSV；生日、城市分配和电话是合成的。这里的“实体”是合成
记录的实验标识，不是经过核实的现实个人身份。这不是完整真实个人数据集。

## 规模与文件

`database.csv`：**10,000 条**库记录，字段为 `record_id, name_local, name_romanized,
dob, city, phone, country`；协议使用姓名、生日、城市、电话四个属性，country 仅作元数据。

`queries.csv` / `labels.csv`：**200 条正式评测查询，160 正例 + 40 负例**。
`calibration_queries.csv` / `calibration_labels.csv`：额外 **200 条校准查询，同为 160 / 40**。
两个查询集合的源条目标识不重叠，正例分别关联不同库记录，负例的源姓名与罗马化别名
均在库外。正负查询都只携带一种姓名形式，并使用相同扰动策略，避免通过“两列是否
都有姓名”直接辨别标签。标签是生成过程产生的真值，不是按相似度反推的标签。

`provenance.csv`：每条库记录与查询的原始姓名、国家、姓名类型、源标识、查询形式和
实际改变的属性；可核查来源与标签。`manifest.json`：种子、源池容量、分布、脚本及
CSV 的 SHA-256。`plaintext_scores.csv`：两套查询的全库明文得分。`validation.json`：
完整结构检查、阈值、全库聚类、top-3 明文参考和少量 HE 冒烟结果。

库覆盖 **21 个国家/地区、六种姓名类型**，不宣称覆盖源库全部 23 个国家。

| 姓名类型 | 库条数 | 评测正例 | 评测负例 |
|---|---:|---:|---:|
| 带重音拉丁 | 3,296 | 30 | 8 |
| 阿拉伯文字 | 1,545 | 30 | 8 |
| 缅甸文字 | 1,334 | 30 | 8 |
| 纯汉字 | 1,517 | 29 | 8 |
| 汉字＋拉丁混合 | 22 | 11 | 0 |
| 普通拉丁 | 2,286 | 30 | 8 |

混合组源池去重后只有 22 条，本版全取而不复制；其正例分给校准/评测各 11 条，
没有该组的库外负例。其余不足配额从真实剩余源池回补，不合成新姓名。
按“原姓名＋国家”去重不等于证明现实中不存在同名者。ID 使用 SHA-256 的 128-bit
前缀，并检查唯一性，未修改旧版生成器及旧 ID。

## 阈值与初步质量

沿用四属性权重 `0.40 / 0.25 / 0.15 / 0.20`，维度仍为聚类 **3,272**、匹配 **3,122**，
均小于 CKKS 4,096 槽位。数据条数增大不会增加单条密文向量的特征维度。

不沿用小样本阈值 `0.485`，也不使用正式评测查询调参。预先固定规则是“校准集所有
查询的最高非目标分 + 0.001”，得到 **tau = 0.6135671549269659**；这是当前校准样本
上的保守规则，不是最优阈值证明，也不保证未知样本零误报。校准与评测共享同一库，
但不共享查询源实体；后续不要根据评测结果反复修改阈值或筛掉难例。

正式 200 条查询的**全库明文检测**：TP=135、FN=25、FP=0、TN=40，Precision=1.0000、
Recall=0.84375、F1≈0.91525。召回分母始终为全部 160 个正例，没有按 tau 筛掉难例。
155 / 160 个正例的明文 top-1 是其目标；这是明文定位参考，协议本身不返回命中 ID。
top-3 聚类参考与 HE 冒烟单列在 `validation.json`，不得把全库明文结果当成加密检测率。

默认 `k=sqrt(n)` 的全库索引已实际构建：100 个簇，簇大小 26–331，补齐矩阵约
**788.4 MiB**，未触及 2 GiB 限制。top-3 明文协议参考为 TP=133、FN=27、FP=0、TN=40，
Recall=0.83125。与全库参考相比，有 2 个可越阈正例因为聚类剪枝额外漏检。

37 项结构/接口/冒烟检查通过，新增生成与统计专项及相关 schema/数据回归为
106 passed、2 skipped；整个 10k 数据重建后六个原始 CSV 逐字节一致。
三条真实 CKKS 查询（2 正 / 1 负）均与其选簇后的明文判据一致；复用同一会话，
未在查询中重发 context。它们约耗时 17.6 s、19.5 s、225.8 s。负例要扫描
`3 × 331 = 993` 列，显示大库下当前第二轮仍有明显性能风险，**不要把“建库通过”
理解为“完整 200 查询能快速完成”**。冒烟中的通信字段是每查询在线负载，未记录
握手总量；这里不把它作为正式端到端带宽结果。

结论：**满足 10k 库 / 200 查询、多语言四属性、标签可追溯、可复现和独立校准的要求**。
适合规模与功能对比；不等于真实联合属性泛化基准、困难负例基准或恶意安全证明。
40 条负例和少量 HE 冒烟不足以证明生产级低误报率或全程稳定性。不同数据集即使同为
10k / 200，也不能仅凭规模相同直接比较准确率。

## 使用与复现

在仓库根目录运行；使用现有 Miniconda 环境。生成器拒绝覆盖已有输出；要核验重建，
请使用新的 `--out` 与 `--config` 路径。固定 seed=20261025，六个原始 CSV 已通过完整
10k 重建的逐字节一致性检查。日期扰动沿用旧逻辑，但对产生 9140 等不合理年份的情况
改为相邻年份，出生日期始终在 1900–2026 范围内。

```powershell
# 新建数据；本目录已经生成，不要原地重复执行
& C:\Users\Dinking\miniconda3\python.exe baseline_Integration/scripts/build_fused_multilingual_benchmark.py

# 重做结构、独立校准、明文与全库聚类检查，并跑少量加密冒烟
& C:\Users\Dinking\miniconda3\python.exe baseline_Integration/scripts/validate_fused_multilingual_benchmark.py --he-smoke

# 正式全库 / 全部 200 查询的加密实验入口
& C:\Users\Dinking\miniconda3\python.exe baseline_Integration/scripts/demo_multi_attribute_dataset.py --config baseline_Integration/config/examples/fused_multilingual_10k_multi_attribute.json --db-limit 0 --limit 0 --probes 3 --k-mode sqrt --no-color --output-dir baseline_Integration/artifacts/demo/fused_multilingual_10k_200
```

通信采用会话复用的新口径：一次握手单列，不能与旧单姓名 172 MB 数字直接混算。
当前协议仍有掩码幅度、时序/早停与恶意输入等安全边界，参见仓库
`docs/reviews/ckks_context_session_audit_2026-10-25.md`。

## 2026-10-25 性能更新

首次完整 HE 长跑按用户要求在 43/200 条时停止，原日志与 checkpoint 保留，没有全量
结果。随后新增 `multi_attribute/batched_protocol.py` 的流式稀疏 SIMD；demo 可用
`--he-mode serial|batched|auto`，默认 auto 在此 10k/200/top-3 配置选批处理。
批模式没有逐查询早停，所有候选统一补齐，时间和通信按整批记录，逐行值明确标注为
摊销值，不是独立请求时延。权重、阈值、维度、聚类及加密参数均未改变。

完整库上四条真实 HE 试跑耗时 86.67 秒，判定、选簇和首命中位置均与明文一致；此前
同四条串行合计 297.54 秒，但非配对计时。小批次固定上传约 2.17 GB，反而高于串行，
所以仅在大批次自动启用。完整 200 条新后端尚未跑，不能据此声称其最终性能或检测率。
细节与阶段对比见 `docs/reviews/multi_attribute_performance_2026-10-25.md`（仓库根目录）。

## 2026-10-26 完整运行结果

现已完成完整 10k / 200 batched HE，并逐条与独立 Top-3 明文参考核对：200/200 一致。
TP/FN/FP/TN = 133/27/0/40，全部正例召回率 83.125%，F1 90.785%。27 条漏检包含
