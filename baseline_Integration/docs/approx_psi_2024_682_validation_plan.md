# Approx-PSI 2024/682：小规模机制验证与基线对照任务

状态：原始实验设计，E0/E1/E2 已在 `../../对比/` 实现并运行；当前结论及复现命令以 [对比/RESULTS.md](../../对比/RESULTS.md) 和 [对比/README.md](../../对比/README.md) 为准。E3 未实现。本文保留原方案及尚未完成的严谨性要求，不把它们写成已完成事实。

目标不是完整复现论文排名，而是判定：二值化、重复投影候选筛选、候选内精确验证，哪些能改善现有姓名匹配；收益来自哪里，是否值得承担隐私协议改造成本。

## 1. 研究对象与边界

论文：[Approximate PSI with Near-Linear Communication](https://eprint.iacr.org/2024/682)，使用 2024-10-13 修订版。本地阅读材料保存在 `artifacts/research/approx_psi_2024_682/`，不作为实验输出。

必须区分两条路线：主 Approx-PSI 的重复坐标投影、秘密分享 PSI 与安全距离验证（Algorithm 1），以及不平衡查询场景的投影分桶、PIR 与安全验证（第 8 节 Algorithm 2）。前者依赖近远间隔；后者不要求同样的 gap，但小桶分析使用均匀二进制数据库假设，不能直接套用到姓名编码。[论文 PDF，第 6、8 节](https://eprint.iacr.org/2024/682.pdf)

正式复现需要密码学子协议，而不是 Python 字典求交。论文第 9 节使用 C++、EMP 和 volepsi；本次未定位到作者完整实现的公开仓库，不等于确认其不存在。先验证机制，不把安装重型依赖作为首要任务。

论文 Table 3 的一个成本参照是：双方各 256 条、128 bit、Hamming 阈值 4、统计参数 40，报告约 38.7 秒和 465.68 MB。这不是当前 200 对 10K 姓名任务，不能据此计算相对我们的加速比。[论文 PDF，第 27 页](https://eprint.iacr.org/2024/682.pdf)

本任务明确区分 `mechanism-only`、`estimated`、`secure-measured` 三种结果；前两者不填写“完整安全协议实测加速比”。

## 2. 当前基线必须先锁定

姓名生产基线是 200 维 MinHash 聚类、50 维 MinHash 匹配、余弦阈值 0.9、二维 CKKS tiled batching。直接读取了 `minhash/encoder.py`、`party_b/offline_prep.py`、`party_a/local_prep.py`、`evaluation/benchmark.py` 与评测脚本。

特别注意：`scripts/evaluate_ncvr_10k.py` 默认 `--batch-size 0`，统一评测示例也配置 `he_batch_size=0`。主对照必须显式开启 batching，不能用默认串行运行制造加速优势。原有多属性模块是另一条路径，本轮不混入姓名对照。

冻结并记录：提交号、工作树差异、解释器与依赖版本、数据哈希、MinHash 种子、预处理版本、聚类数、阈值、实际批大小、CKKS 参数、上下文复用与 early-stop 设置。模型准备只使用 B 方数据。

历史 README 的耗时只用于规划量级，不作为新实验结果。现有 `memory_peak_mb` 来源于离线阶段 `tracemalloc`，不能当作整个进程/TenSEAL 原生内存峰值；正式实验另测进程及必要子进程 RSS。

最终原始数据回归的命令模板如下，必须先确认实际 Python 环境可导入 TenSEAL：

```powershell
python scripts/evaluate_ncvr_10k.py --batch-size 200 --k 50 --tau 0.9 --fuzzy-ratio 0.3 --fuzzy-seed 42 --no-early-stop --output-dir artifacts/evaluation/approx_psi_2024_682/baseline_reference
```

该命令只覆盖既有 200 条查询回归，不会自动产生下面的分层开发/测试集。其余实验需要独立驱动，不能只用 `--query-limit` 截前若干条：原始查询先排正例、再排负例。

## 3. 先检查一个可能决定路线的几何限制

当前最终匹配向量由非负 MinHash 数值做 L2 归一化，非零向量之间余弦非负。标准化只用于聚类，不能拿聚类向量替换最终匹配向量来规避限制，否则已经改变匹配语义。

我们自己的推导：定义归一化角距离 `a=acos(cosine)/pi`。固定阈值 0.9 对应半径约 `0.143566`，而非负向量的最大角距离只有 0.5。如果希望所有非匹配点距至少为该半径的 g 倍，则必要条件是 `g <= 0.5/0.143566 ≈ 3.4827`。

因此，保持该阈值和表示时，存在非匹配点的非平凡数据不可能满足 `g=4/8` 的原始角距离分离条件。二值嵌入还有误差，不能把论文 Hamming 实验的 gap 直接照搬。这个结论不否定投影筛选作为经验方法，也不否定第 8 节路线；改变表示或阈值时必须作为单独实验。

更紧的“实际正例最大距离”可能产生更好的经验 gap，但不能据此宣称覆盖原始阈值下的所有潜在匹配。

## 4. 数据与最小实验矩阵

| 阶段 | 数据规模 | 要回答的问题 | 执行范围 |
|---|---|---|---|
| E0 前提审计 | NCVR B=1,000，现有查询200；再对10K只做向量/桶统计 | gap、二值化和桶负载是否适用 | 明文，无 HE |
| E1 机制自检 | 合成二进制 A=B=128、256、512 | 在满足/违反假设时算法行为是否正确 | Algorithm 1 明文模拟 |
| E2 应用对照 | NCVR B=1,000、5,000、10,000；查询200 | 相同质量下候选和成本有没有下降 | 明文筛选与局部成本测量 |
| E3 安全试验 | 先 B=1,000/Q=32；通过后 B=10K/Q=200 | 加上真实隐私代价后是否仍划算 | 有条件执行 |

只在 B=1,000 的开发集选参数，其余规模沿用；不做所有参数与所有规模的笛卡尔积。E3 小实验只跑基线与一个胜出方案。

当前实现将原始 200 条查询按正负标签各自打乱，分成开发100条（50正/50负）和测试100条（50正/50负），并检查查询 ID、基础规范姓名和目标记录 ID 不跨组。三个随机种子重复使用同一批查询实体，只改变扰动/投影；因此不是 300 个独立样本。投影搜索范围曾在查看测试结果后扩展，现有 E2 统一标为后验探索，不再称“锁定独立测试”。已另做 100 正/100 负的新查询实体跟进测试，参数不再调整；但其样本仍是事后便利抽样、负例未人工做模糊姓名歧义判定，不能视为总体代表性确证。

当前使用原数据管线的前 1K/5K/10K 条原始 B 记录，并与真实 benchmark 一样按可检索姓名去重；10K 输入实际对应 9,933 个可检索姓名。当前查询的正例目标已检查存在；尚未保存独立的 record_id 抽样清单。

保留原始精确查询；在同一组内生成替换、删除/插入、相邻字符交换以及双字符扰动。另建困难负例切片，必须检查其库内目标与标签是否成立，不能把随机打错姓名直接标为负例。每种扰动单独报告；来自同一实体的多条变体不算独立样本。

本轮主任务仍是“姓名是否存在近似匹配”，NCID 作为来源追踪而不天然等于语义真值。对不同 NCID 的规范化同名、同音/近名人工审计并列为歧义切片。实体链接指标另报，不能混用。

## 5. E0：低成本前提审计

使用最终匹配的50维向量，保留200维聚类流程不变。计算真目标、每查询最近非目标、随机负例三类的余弦/角距离分布。记录全库阈值命中个数，防止只比较真目标而遗漏更相似的其他记录。

在1K数据上检查 A-A、B-B、A-B 的距离；记录 `r < distance < g*r` 的灰区比例和每查询是否存在灰区邻居，而不只给全局平均。10K阶段分块计算或明确标注抽样；抽样未发现违反不能证明全局假设成立。业务标签与距离关系分开审计。

做一个简单、明确标为工程替代的随机超平面符号编码：`b(x)=1[R x >= 0]`，长度128/256/512 bit，同一 R 用于两方。它用于测试角距离到 Hamming 的可用性，不宣称精确复现论文引用的嵌入构造。不要把MinHash整数直接展开成二进制并假定保留余弦距离。

测二值化前后决策翻转、真目标召回、困难负例误报、阈值附近误差；记录每bit频率、相关性和实际桶负载。单bit接近50%不代表整个码字均匀或独立。开发集校准阈值后锁定测试。

若二值化单独造成不可接受的召回下降，停止将它作为最终判定器；仍可测试宽松候选筛选后用原余弦精判。

## 6. E1：论文主机制的最小功能复现

合成128-bit向量，阈值4，测试 gap 4、8；每个规模先验证生成数据确实满足组内分离与跨组近/远关系。构造50%匹配、50%不匹配，近匹配通过翻转至多4 bit生成；生成后枚举验证，不用“随机数据大概够远”代替检查。

按 Algorithm 1 的聚类代表、坐标抽样、同投影冲突随机留一、交集候选与Hamming精判执行明文模拟；精确穷举作为答案。多对一近邻、重复元素必须另设单元测试，代表到原记录的展开不能静默丢失。

采用论文第6节/附录H的参数计算，先复核 `n=256, gap=8, lambda=40` 得到96轮作为公式测试。再测试工程轮数16/64/128，分别标注经验召回，不把它们自动解释为 `2^-40` 失败概率。统计参数与计算安全参数分开记录。

增加“破坏假设”的对照：注入距离落在灰区的向量、让10%记录形成密集近邻群。比较召回、冲突丢弃率和每轮候选数；不能为了曲线好看删掉真实拥挤样本。

本阶段输出是机制正确性、轮数-召回曲线及候选工作量，没有安全通信实测。Python set/dict 只是本地模拟，不向真实对方公开投影交集。

## 7. E2：最有价值的应用消融

| 组别 | 表示 | 候选选择 | 最终判定 | 解释 |
|---|---|---|---|---|
| O 全库参考 | 原50维向量 | 全库 | 原余弦阈值 | 分离聚类漏召回与特征问题，不是生产替代 |
| B 当前基线 | 原50维向量 | 当前200维聚类选一簇 | 原余弦阈值 | 主对照，安全版使用tiled batching |
| H 二值化消融 | 128/256/512 bit | 与B完全相同的候选 | Hamming阈值 | 单独测二值化损失，不重做聚类 |
| P 投影筛选+原精判 | 同一二值码用于筛选 | 重复坐标投影分桶、合并候选 | 原50维余弦阈值 | 优先验证的可借鉴逻辑 |
| PH 投影筛选+二值精判 | 同P | 与P相同 | Hamming阈值 | 与P比较最终距离算子的影响 |

P/PH 借鉴第8节候选组织方式，但第一阶段只在本机拿到候选；不是PIR实现，也不是安全协议。投影操作是从二值码取坐标，不是再执行一次稠密随机线性变换。

原计划的参数搜索范围是 `s-2/s/s+2`；实际运行曾在查看测试后扩展到 `s+10`，所以后续结果只作为探索性证据，不作为预注册确证。s表示桶索引长度，g表示主协议gap。全程复用嵌入和投影前缀，使对比可配对。

对未进行按负载拒绝采样的独立均匀定长坐标投影，Hamming距离h的两点单轮同桶概率为 `q=C(ell-h,s)/C(ell,s)`，R轮至少一次同桶概率为 `1-(1-q)^R`。用它校验模拟与制定轮数，不直接把均匀投影结论用于按桶大小反复重采样后的条件分布。若采用该重采样，单独报告次数及经验召回。

记录真实候选去重数，以及隐私执行需要处理的填充槽数、轮间重复比较数和索引总存储。尤其不能用“本地去重后只剩几个候选”冒充安全协议也只付出几次比较的成本。

桶溢出不能静默截断。预先定义公开容量、填充策略、重采样次数上限和失败处理；大桶可标记该参数失败。任何回退的触发信息、时间和额外泄漏都要计入后续协议设计。

## 8. E3：安全代价核算，而不是立即重写协议

进入条件：P至少在两个规模上有一致的候选收益，阈值/轮数没有针对测试集挑选；结合填充与重复工作量后仍有下降空间。B=1K/Q=32的正负样本分层抽取，不截前32条。

路线A：如果取得作者实现或能够复用合适密码学库，先运行小规模合成协议自检，再实现与基线相同的A方逐查询存在性输出。不能用暴露匹配对/中间距离的输出与现有输出直接等价比较。

路线B：若暂时无完整实现，只测当前CKKS核、序列化及候选组织的局部成本，给出“允许的安全候选获取开销”：`预算 = 基线在线时间 - 新精判及其他固定时间`。用这个预算判断是否值得投入PIR/SS-PSI接入，不能填造其耗时或通信量。

公开查询桶号、候选记录ID、投影交集、桶实际长度或明文候选均不视为完成隐私化。也不能直接把查询相关候选发给B再声称复用现有HE就保持了原安全边界。

候选列表变短不必然使现有密文核等比变快：当前selector仍涉及所有簇，列矩阵按最大簇补齐，SIMD容量又取决于批大小。需要测实际kernel/tile数量、packing利用率和padding，而非仅按候选个数线性外推。

若安全核和打包收益本身不足以抵消开销，就结束在机制验证，不把整套C++协议复现升级为默认任务。

## 9. 测量、成功门槛与交付

匹配指标：Precision/Recall/F1、FP/FN计数、按扰动切片的结果；候选集合对真目标和对全库阈值命中的召回；每查询候选数均值/P95/最大值、桶填充量、重复比较与建库占用。

性能指标：预处理/建库、密钥及公开context设置、查询编码、候选获取、距离计算、序列化/解密分别计时；通信同时报首次含设置与热查询复用两种口径。记录真实双向bytes及交互轮次。单进程回环结果不能当作WAN时延，带宽/RTT外推必须标成估算。

固定种子42/43/44，先配对重复明文实验；真实性能固定输入预热后测三次，报告中位数与范围。保持CPU、线程、批大小与上下文复用一致，主试验统一关闭early-stop。B=10K/Q=200固定显式批大小200；Q=32固定32。摊销每查询耗时与单查询延迟分列。

预先约定的工程筛选线（不是统计显著性证明）：在开发集相同误报约束下，候选召回尽量接近全库参考，且测试集不新增观察到的漏报；填充/重复后的工作量有至少2倍下降，或安全实测时间/通信有至少30%下降且另一项不出现不可接受增长。只达到其中某一资源收益时按具体部署约束判断，不强制宣称全面更好。

测试只有约50个独立正实体，不能据此证实1个百分点级召回差异或极低失败率。报告逐例变化与实体级置信区间；接近决策边界时扩展独立实体，而不是增加同一姓名的重复扰动来虚增样本。

建议交付：固定数据划分与配置、明文机制单元测试、逐查询CSV和汇总JSON、召回-候选工作量图、二值化错误切片、分阶段耗时/通信图，以及一页取舍结论。完整协议未做时，其对应列明确写“未实现/未测”。

实际实现统一放在相邻的 `../../对比/`，原仓库生产协议未改动，原代码通过导入复用。明文原始结果放在 `../../对比/artifacts/final_comparison/`，HE 数值审计放在 `../../对比/artifacts/he_equivalence_audit.json`，实体不重合便利样本结果放在 `../../对比/artifacts/entity_disjoint_holdout.json`；这些产物不提交 Git。后续若继续做代表性样本与歧义人工审定、E3，再按实际实现更新本节，不修改 `.gitignore`。

最终结论按四类落地：完整路线值得继续；只借鉴投影筛选与原余弦精判；只借鉴二值表示；因距离分布/桶拥挤/隐私代价不适合。负结果必须保留触发原因与反例。

执行优先级：先E0与E1，再E2；只有E2显示明确机会才进入E3。最优先回答的是“保留原精判、换候选组织是否有用”，而不是“能否复现论文20倍”。
